## 2. Admin access

### Failed case: `Permission denied (publickey)` when restoring sudo

- The `ssh -t chedam "…sudo tee…"` command was typed **inside an SSH session on the Pi** (prompt `chedam@chedam:~ $`).
- So the Pi tried to SSH into itself and had no key for that. Re-flashing was not needed.
- Fix: run only the inner command on the Pi:

```
echo 'chedam ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/010-chedam && sudo chmod 440 /etc/sudoers.d/010-chedam
sudo -n true && echo OK
```

## 3. Display becomes a switch (DL-24 updated)

Sreya's requirement: the monitor is optional on the Zero 2 W pilot, but the option must stay. Pi 4 production hubs will use a display to operate the hub directly.

Change in `hub/scripts/setup-hub.sh` (boot config section):

- Removes any earlier chedam block, then writes a block between `# chedam-begin` and `# chedam-end`.
- `--keep-display`: display driver `vc4-kms-v3d` and display detection **on**, Bluetooth off.
- No flag: headless. The display driver and detection are off, `gpu_mem=16`, Bluetooth off; this saves ~50 MB of RAM.
- Audio and camera detection are always off.

```

sudo bash ~/hub/scripts/setup-hub.sh                  # headless
sudo reboot                                           # after switching
```

### Failed case: an extra `[all]` line on every run

- The test (switching off, on, off, on on a copy of `config.txt`) worked, but each run appended another `[all]` line. It was harmless but untidy.
- Fix: moved `[all]` inside the marked block. The original config (`config.txt.chedam-orig`, saved by the first run) was restored and setup run twice. Both runs gave the same checksum (`d91ff929`), and the only differences from the original were audio off, camera detection off and the chedam block.

### Design choices

- **Common fields:** `id` (a device may create it offline), `created_at`, `updated_at`, `created_by`, `updated_by`, `device_id`, `deleted_at`. `updated_by` was added beyond the spec's list, so each change records who made it.
- **The event log runs inside the same transaction** as the change (`onRecord*Execute` + `runInTransaction`). If the event can't be written, the change is rolled back, so the log never misses a write.
- **Actor and device are stamped by the hub** in request hooks. A client cannot forge `created_by`, and the device comes from the `X-Chedam-Device` header (verified in step 4).
- **Hidden fields** (`pin_hash`, `recovery_code_hash`, `key_hash`, `pairing_code_hash`) never reach the API or the log.
- **Role levels:** owner 100, manager 80, accountant 50, cashier 40, staff 30. Owner-only permissions: modules.manage, setup.run, owner.manage, backups.restore, updates.install.
- **Sample data is separate** from real migrations, so a store hub never receives demo records.

### Failed cases and fixes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `pocketbase.exe: command not found` in Git Bash | That shell started before `C:\Tools` was added to PATH | Full path `C:\Tools\pocketbase.exe` / `PB_BIN` |
| `migrate down` hung | It waits for a y/N confirmation | Pipe `y` (`input: "y\n"` in the tests) |
| Python check query error (`ESCAPE expression must be a single character`) | Backslash escaping in an inline script | Filter with `substr(name,1,1) != '_'` |
| Sample migration: `Cannot read property 'forEach' of undefined` | A JSON field read with `get()` returns raw bytes | `JSON.parse(record.getString("value"))` |
| Test stop step hung | Waited for the exit of a process that had already exited | Check `exitCode`/`signalCode` first |
| Create returned 400 "Something went wrong" | `e.request` doesn't exist in PocketBase 0.40 JS hooks (found with `serve --dev` logs) | `e.requestInfo().headers["x_chedam_device"]` (names lowercased, `-` → `_`) |
| A Python edit put real newlines inside JS strings | Escaping in a heredoc | Fixed with a direct edit |
