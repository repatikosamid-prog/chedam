### Failed case: `mkcert` not recognized

- Symptom: `mkcert -install` → "The term 'mkcert' is not recognized".
- Cause: the file was still named `mkcert-v1.4.4-windows-amd64.exe`, and `C:\Tools` was not on PATH. PowerShell also never runs a program from the current folder without `.\`.
- Fix: copied `mkcert.exe`, `pocketbase.exe` and `duckdb.exe` to the top of `C:\Tools` and added `C:\Tools` to the user PATH. A new PowerShell window was needed for the change to show.

Then Sreya ran `mkcert -install` (local dev CA added to the Windows trust store) and `gh auth login` (fine-grained token).

The installers folder was added to `.gitignore`. PocketBase had created test data there.

## 3. Flashing the Pi (first time)

Imager settings: Pi Zero 2 W, Raspberry Pi OS Lite 64-bit, hostname `chedam`, user `chedam`, Wi-Fi 2.4 GHz, country CA, time zone America/Vancouver, SSH public-key only.

### Failed case 1: hostname and username

- The hostname was typed as `Chedam` and the username as the GitHub name.
- Fix: lowercase `chedam` for both, so every script and guide matches.

### Failed case 2: no SSH key existed

- SSH was set to password authentication, and the PC had no key yet.
- Fix: `ssh-keygen -t ed25519 -C "chedam-dev"`.

### Failed case 3: `Permission denied (publickey)`

- Debug output showed the PC offering its key and the Pi refusing it for both usernames:

```
ssh -v -o BatchMode=yes chedam@chedam.local true
```

- Cause: the key written to the card was not the PC's key.
- The "host key differs" warning came from an old `192.168.1.241` entry in `known_hosts`. It was removed with `ssh-keygen -R`.

### Failed case 4 (security): private key pasted into Imager

- Imager listed 7 "keys". They were the 7 lines of the **private** key (`BEGIN OPENSSH PRIVATE KEY`).
- Risk: the private key was copied onto the SD card and partly shown in a screenshot.
- Fix: removed all 7 entries, deleted the key pair, generated a new one, and pasted **only** `id_ed25519.pub` (one line, `ssh-ed25519 … chedam-dev`). Re-flashing overwrote the card.

### Failed case 5: `.local` name not resolving from Windows tools

- Git Bash ssh and Windows ssh both failed on `chedam.local`, while `Resolve-DnsName` worked.
- Fix: an SSH alias `chedam` pointing at the IP, in `~/.ssh/config`. The Pi first booted slowly (~5 min), so early checks also failed.

Login worked: `chedam@chedam`, Debian 13 trixie, aarch64, 415 MB RAM, 117 GB card.

### Admin access

`sudo` asked for a password, so Sreya ran this once:

```
ssh -t chedam "echo 'chedam ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/010-chedam && sudo chmod 440 /etc/sudoers.d/010-chedam"
```

## 4. Hub setup (first time, Pi at 192.168.1.241)

OS update (ran in the background, ~15 min):

```
sudo apt-get update && sudo apt-get -y full-upgrade && sudo apt-get -y install chrony sqlite3 ufw
```

PocketBase 0.40.4 linux_arm64 was downloaded on the Pi and checked with `sha256sum -c` against `checksums.txt`.

Files written in the repo:

| File | Purpose |
| --- | --- |
| `hub/scripts/setup-hub.sh` | Idempotent setup: packages, service user `chedam-hub`, `/opt/chedam`, PocketBase service, Caddy, watchdog, journald, Wi-Fi power save off, boot config, firewall |
| `hub/system/chedam-hub.service` | PocketBase on 127.0.0.1:8090, auto-restart, `GOMEMLIMIT=100MiB`, `MemoryMax=220M`, hardening |
| `hub/system/Caddyfile` | HTTPS for `chedam.local` and the hub IP, using a per-store CA; plain HTTP only for `/ca.crt` |
| `hub/system/watchdog.conf` | Hardware watchdog 14 s |
| `hub/system/journald.conf` | Logs capped at 64 MB (SD card wear) |
| `hub/system/wifi-powersave-off.conf` | Lower Wi-Fi latency |
| `hub/system/index.html` | Placeholder page "Chedam hub is running" |

Run on the Pi:

```
scp -r scripts system chedam:hub/
ssh chedam 'sudo bash ~/hub/scripts/setup-hub.sh'
ssh chedam 'sudo systemctl reboot'
```

### Failed case 6: GitHub repo creation

- `gh repo create … --public` → "Resource not accessible by personal access token".
- Cause: the fine-grained token cannot create repositories. Sreya has to create the public repo on github.com.

### Failed case 7: HTTPS tests from the PC returned nothing

- Windows `curl` (Schannel) → "the revocation status is unknown". A private CA has no revocation server.
- Fix for command-line tests: `--ssl-no-revoke`. Browsers are not affected.

### Failed case 8: Caddy error at start

- Caddy tried to install its root certificate into the Pi's own trust store and failed ("failed to execute sudo").
- Fix: the `skip_install_trust` global option in the Caddyfile.

## 5. Decisions recorded (docs/P0-mini-spec.md)

| ID | Decision |

Findings:

- Android 9 cannot resolve `.local`, so the hub needs a fixed IP.
- Android 9's Chrome no longer gets updates.
- Caddy leaf certificates last 12 hours, so the clock must be correct (RTC for the pilot).
